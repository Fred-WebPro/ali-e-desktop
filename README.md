# Ali-E CRM — приложение для Windows

Оболочка вокруг развёрнутого веб-приложения `app.aliecrm.com`.

## Почему именно так

Приложение не содержит копию сайта внутри, а открывает боевой адрес. Отсюда
два следствия, оба в плюс:

- **каждый деплой веба сразу попадает в десктоп** — выпускать новую версию
  установщика ради правки интерфейса не нужно;
- **данные живые**: та же Supabase, включая realtime-подписки, которые в вебе
  уже используются в 48 местах.

Обратная сторона: без интернета приложение работать не будет. Это осознанное
решение — оффлайн-режим требует локального кэша и разбора конфликтов правок,
что кратно дороже и на старте не нужно.

## Что внутри, кроме окна

Чтобы это не ощущалось «браузером без адресной строки»:

- своё меню на русском, горячие клавиши (F5, Alt+Home, масштаб);
- внешние ссылки открываются в системном браузере — пользователь видит
  адресную строку и замок, а не чужой сайт без опознавания;
- переход на посторонний домен внутри окна запрещён;
- размер и положение окна запоминаются между запусками;
- иконка в трее, второй запуск поднимает уже открытое окно;
- экран «нет связи» вместо белого полотна;
- тёмный фон до первой отрисовки — без белой вспышки при старте.

## Безопасность

`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`. Страница
не имеет доступа к Node — проверено: `typeof require` внутри окна возвращает
`undefined`. Мост `window.aliEDesktop` отдаёт только факт «это десктоп»,
версию и платформу.

## Про баннер беты

User-Agent намеренно подобран так, чтобы **не** совпасть с маркерами
`AliEApp` / `AliE-Native` из `ali-e-crm/src/utils/native.js`. Эти маркеры
включают «нативный режим» и прячут баннер открытой беты. Скрывать от клиентов,
что продукт в бете, мы не будем.

## Сборка

```
npm install
npm run dist
```

Результат: `release/Ali-E-CRM-Setup-<версия>.exe` (~78 МБ), установщик NSIS с
выбором папки, ярлыками на рабочем столе и в меню «Пуск», деинсталлятором.

Для проверки без сборки: `npm start`. Другой адрес — через переменную
окружения: `ALIE_URL=https://staging.example.com npm start`.

## Подпись кода — не сделана

Сейчас установщик не подписан, и Windows показывает SmartScreen
«Неизвестный издатель». Когда появится сертификат, подпись включается двумя
переменными окружения перед сборкой, менять код не нужно:

```
CSC_LINK=путь_к_сертификату.pfx
CSC_KEY_PASSWORD=пароль
```

## Автообновление — пока не работает

В `package.json` прописан источник обновлений: GitHub, репозиторий
`Fred-WebPro/ali-e-desktop`. **Этого репозитория ещё нет**, поэтому проверка
обновлений тихо завершается ошибкой и не мешает работе.

Чтобы включить:

1. создать репозиторий `ali-e-desktop`;
2. выдать токен: `set GH_TOKEN=...`;
3. `npm run release` — соберёт и опубликует релиз.

После этого установленные копии будут сами скачивать новые версии и
предлагать перезапуск.
